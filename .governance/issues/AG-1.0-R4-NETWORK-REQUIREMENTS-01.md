# Issue Trace — AG-1.0-R4-NETWORK-REQUIREMENTS-01：受控网络研究与外部资料边界

## 1. 用户可见问题

现有能力基线把网络研究写为“待确认”，而 AG 的延期项又笼统写作“网页抓取”。这会使用户、产品与实现方无法区分：用户明确要求查资料时的有限公开网页研究，和自动爬虫、认证浏览或外部文件导入等高风险能力。

## 2. 本轮人类确认

1. `CAP-14` 纳入 Agent 1.0 的 P1 受控能力。
2. 只有用户明确要求搜索/核验，或明确提供 URL 时，才可搜索公开网页或有限读取结果页。
3. 对每个实际使用来源，结果应展示标题、域名、URL、获取时间，并区分事实、推断和未知。
4. 外部网页与搜索结果均为 data-only；可支持回答或 ChangeProposal，不能直接改动逻辑或磁盘状态，也不能扩大指令、权限或编辑目标。
5. 默认只向外发送查询或用户显式提供的 URL；不得上传本地文档、选区、项目树、会话历史或本地文件。
6. 爬虫/批量抓取、登录、表单提交、付费墙绕过、下载/导入、localhost/内网/私有网络访问不纳入 1.0。
7. 无结果、网络失败或来源不可访问时必须诚实反馈，不得伪造来源或引用。

## 3. 需求边界

- 本轮只冻结网络研究的用户可见范围、数据外发边界、来源表达和 P1 档位；不定义 provider、网络工具、接口、请求参数、地址校验算法、存储字段或爬取技术。
- 网络研究是显式用户动作，不是 Agent 的自动背景行为；外部资料只作为不可信输入，不能触发工具、写入或权限升级。
- 由网页资料形成的文档变更仍走既有 ChangeProposal、预览、裁决与显式保存链。
- AG 负责发起受控研究并表达分析；REF 只承接来源引用和 data-only 供给，不发起任何网络请求。

## 4. 直接消费者

- AG：CAP-14 及 REQ-AG-010 承接显式触发、公开访问范围、最小数据外发、来源化分析、失败反馈和编辑隔离。
- REF：REQ-REF-007 承接已使用来源的可见、可回看引用；外部文件维持仅元数据引用。
- CORE 需求索引：记录 R4-A 已确认，但 R4 其余子项和 R5 仍未冻结。

## 5. 验收计划

- CAP-14、外部网页矩阵、AG/REF L1 需求和索引对 P1、显式触发、data-only、最小数据外发及禁止项一致。
- AG 的“网页抓取延期”只指自动或批量抓取，不覆盖已经确认的有限公开网页研究。
- 每个实际使用的网页来源均需可追溯；失败、无结果与不可访问来源不伪造成功。
- 实现后以公开查询、显式 URL、无结果/访问失败、网页注入文字和“依据资料编辑”的真实样例验证；未验证时入口保持关闭。
- 本 Scope 不运行代码测试；网络执行器与验证矩阵属于后续 DESIGN Scope。

## 6. 待设计项

- 网络 provider、工具授权、请求预算、超时/重试、取消和错误形状。
- 公开地址与重定向校验、可允许域名/条款策略、robots 与数据处理合规边界。
- 来源稳定身份、快照/摘录范围、重新校验、保留期限及跨会话展示。
- 网络输入的提示注入隔离、Trace 脱敏和真实系统验证矩阵。
