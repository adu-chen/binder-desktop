# Binder 总开发实施计划（程序级 L3）

## §1 文档定位与读法

- **与路线图（A-CORE-X-L-01）分工**：路线图排"建什么文档、什么顺序、依赖怎么排"；本文排"怎么
  落地实施、每阶段过门禁的验收标准是什么"。两者均为程序级编排，不产出规则。
- **门禁纪律**：G1–G6 语义见 APC §5；**未过前一门禁不得进入后一阶段**；AI 可建议晋级，**晋级由
  人类宣布**（APC §2）。本文「验收标准」= 该阶段过门禁的可核验条件清单，达成后由人类宣布晋级。
- **门禁状态（2026-06-12，人类宣布晋级）**：客户端 15 模块 L1+L2+I-P 文档齐备、12 台状态机
  active、ADUS 15 模块/60 规则/22 链路/13 约束/23 术语、前端交互总图就位；`governance:audit`
  仅余「无代码」预期空发现项。**人类于 2026-06-12 宣布全部客户端模块 G1（需求）与 G2（技术设计）
  闭合，正式进入 G3（开发计划）。**
- **AG 模块门禁例外（人类决定，留痕）**：债务台账（A-CORE-X-R-01）识别 AG 有 4 项 B 类设计缺口
  （B-1 提示词组装架构 / B-2 AG↔AST 记忆写入触发 / B-3 AG↔CBT 接管 AG 侧建模 / B-4 跨文档产出
  边界）。人类决定**不在 G2 前补，降级为 G3 强制承接**——这 4 项必须写入 AG 的 G3 Plan Item
  作为强制承接条目（不得遗漏），在 G4 实现前补齐设计并经 DE 复核（B-4）。此为人类承担的门禁
  例外，AG G2 闭合附此条件。
- 云端域（AUTH/GW/LIC/PORTAL）独立 APC，门禁独立推进，不在本次客户端闭合范围。

## §2 总体实施策略

1. **文档→实现的转换单元 = Plan Item**：各模块进 G3 时产出承接型 Plan Item（A-{M}-X-L-01），
   每条 Plan Item 承接 REQ/RULE/CHAIN/CONSTRAINT/状态机，明确文件范围与 @GOV 落点（APC §5 G3）。
2. **状态机驱动**：状态化核心链先有状态机（已全部 active），实现时 @GOV 追溯规则、转移测试矩阵
   强制覆盖（APC §6/§10）。
3. **契约打桩先行**：云端 AUTH/GW/LIC 未实现期间，AI 链按 A-SYS-I-P-03 契约打桩，使 P3 可独立
   推进（路线图 §4 注）。
4. **audit 硬阻断常态化**：`governance:audit` failed 阻断 READY/合入/发布，无报告-only 宽限
   （APC §12）；每阶段实现以 audit 绿为底线。
5. **核心链优先**：编码起点为「对话→diff→裁决→落盘」与「workspace/编辑底座」，先打通主干再铺
   上层与商业化。

### P2 workspace 与编辑核心（WS / ED / DOC）

- **范围**：本地文件/编辑底座——workspace 生命周期、save 与外部变更冲突、时间轴、TipTap 编辑
  运行时、blockId、docx 双链（Pandoc 编辑 / LibreOffice 预览）。
- **前置**：P1 过 G2/G3（SYS 契约可依赖）。
- **产出**：WS/ED/DOC 实现 + 各自 Plan Item；workspace.db 完整 schema 落地。
- **验收标准**：
  - 文档侧：WS/ED/DOC 的 L1+L2+I-P 齐备（**已达成**），G1/G2 待人类宣布。
  - 实现侧（G4，待启动）：
    - workspace 打开/切换/关闭；越界路径被拒（X-FORBID-004 测试）。
    - save 原子落盘、无半落盘；**外部修改冲突**走 saveConflict→显式 override/reload（SM-WS-01
      含冲突路转移测试通过）。
    - 时间轴落盘/还原各记一个节点、version_seq 单调；还原失败保持现状（SM-WS-03 矩阵）。
    - md/docx 共用编辑模型；blockId 稳定性（普通编辑不变、删除失效不复用）；docx 往返必需样式
      子集保真 ≥95%（回归测试强制，BR-DOC-DATA-002）；编辑链/预览链分离（render_preview 失败
      不影响编辑链）。
    - SM-ED-01（含 Conflicted）/SM-DOC-01 转移测试通过；@GOV 追溯 BR-WS-*/BR-ED-*/BR-DOC-*；
      `governance:audit` 绿。
- **门禁**：M2 编辑核心可用（P2+P3 核心过 G4 → alpha 内测）。

### P3 对话编辑与 Agent（DE / AG / REF）

- **范围**：产品核心交互「对话→diff→裁决→落盘」+ 工具调用 + 内联辅助 + @mention。
- **前置**：P2 编辑底座 + P1 门禁/网关契约（可打桩）。
- **产出**：DE/AG/REF 实现 + Plan Item。
- **验收标准**：
  - 文档侧：DE/AG/REF L1+L2+I-P 齐备（**已达成**）。
  - 实现侧（G4，待启动）：
    - **门禁不可绕过**（强制）：静态可查无不经 GatePassed 的模型调用路径；无订阅时 chat 拒绝、
      assist 静默（BR-AG-VERIFY-001 / X-SEQ-001 / X-FORBID-002）。
    - **唯一落盘路径**：AI 修改必经 AG 产出→DE diff→人类裁决→WS 落盘；工具调用无旁路直写
      （X-FORBID-006 静态+集成）。
    - diff 三终态互斥不可逆；accepted 唯一触发落盘、ApplyError 不回退（SM-DE-01 矩阵）；过期保守
      （检测不可得不误杀）；多 diff 冲突重检不覆盖新内容。
    - 辅助采纳=用户编辑（经 ed.apply_edit，非 diff）；@mention 为只读注入（无写句柄）。
    - SM-AG-01/02/03、SM-DE-01 转移测试通过；@GOV 追溯齐；`governance:audit` 绿。
- **门禁**：M2（与 P2 合并过 G4 → alpha）。

### P4 上层能力（CBT / AST / KB / TPL / PRV）

- **范围**：多文件构建与接管、本地记忆、知识库、模板工作流、多格式预览输出。
- **前置**：P3 核心链（CBT 依赖 AG/DE；AST/KB/TPL 依赖 AG）。
- **产出**：五模块实现 + Plan Item；workspace.db 控制态扩展表落地。
- **验收标准**：
  - 文档侧：五模块 L1+L2+I-P 齐备（**已达成**）。
  - 实现侧（G4，待启动）：
    - CBT 跨 ≥2 文件构建；计划须确认、失败不静默跳步、中断无半成品、重启可恢复无悬挂；
      Chat↔Build 接管双向回执无双活双死（SM-CBT-01 矩阵）；产物走 diff 路径。
    - 本地资产 **workspace 级隔离**（切换即切换资产集，跨 workspace 不可见）；记忆自动写入可见/
      可溯源/可撤销、撤销不可复活（SM-AST-01）；知识库**本地检索无内容上行**（网络核验强制，
      BR-KB-DATA-002）；TPL 工作流确认点强制、不跳步（SM-TPL-01）。
    - PRV **只读**：全产品无 Excel/PPT 编辑入口（静态+交互核验，BR-PRV-DATA-001）；docx/Excel/PPT
      经 DOC 预览链、音视频系统解码、失败态明确不空白；导出落 workspace 内。
    - 控制态扩展表迁移受 BR-SYS-PERSIST-001 约束；`governance:audit` 绿。
- **门禁**：M3 全功能集成（P4 过 G4 + 跨模块 G5 → beta）。

## §5 关键路径与风险（承路线图 §8）

1. **商业化链路 greenfield**：P5 依赖云端 AUTH/GW/LIC 实现——云端 APC 已立项但代码未启动，是
   GA 的关键路径瓶颈；P3/P4 期间以契约打桩解耦，但 G5 真联调必须等云端就绪。
2. **高频门禁延迟**（ENT-03）：autocomplete 逐次门禁的延迟由服务端短时裁决凭证解决（云端
   REQ-CLOUD-002/CLOUD-04），方案须过 X-FORBID-002 一致性复核；P5 前不得以客户端缓存通过绕过。
3. **docx 往返实测**（DOC-02）：blockId 经 Pandoc 往返保留度需 P2 实现期实测，不达走重建锚降级。
4. **NFR 量化阈值未定**：性能预算/延迟目标在 G5 标定（APC §9），本文 P5 验收的「达标」待标定后
   回填具体数值。
5. **晋级纪律**：各阶段验收达成后由人类宣布晋级，AI 不自行判定门禁通过（APC §2）。
