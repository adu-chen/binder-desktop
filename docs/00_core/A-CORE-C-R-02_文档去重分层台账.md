# 旧 Binder 文档去重分层台账

## §1 台账目的与方法

旧 binder（`/Users/chenzhenqiang/Desktop/test/binder-project`）的 193 个文档全部为本项目
L4 只读参考原料（APC §3）。本项目 REQ 重新撰写，不继承旧文档为权威（APC §8）。本台账
回答一个问题：**当为某个新模块撰写 REQ / 技术设计时，应优先挖掘哪些旧文档、忽略哪些。**

方法与边界（诚实声明）：
- 分类依据 = 旧项目自带的结构清单（`A-CORE-C-R-01_项目文档结构清单`，已定义 状态 A/R/X、
  模块、类型、职责编码）+ 旧 CLAUDE.md 的"当前权威 / 已过时 / 重复对"判定 + 文件名语义。
- **未逐篇通读 193 篇全文**：本表是路由表，不是内容审计。每篇的内容真伪、与代码的一致性，
  在该模块进入 G2（技术设计）实际取材时核对——届时旧文档是原料，新设计是规则源。
- 旧文档物理上不拷入本项目，按绝对路径只读引用。

## §2 处置词汇

| 代码 | 含义 | 取材动作 |
|---|---|---|
| **P1** | 主源 | 撰写该模块新设计时**优先通读**，作为现状/意图的第一手原料 |
| **P2** | 辅助 | 需要补充背景或调研依据时再查阅 |
| **P3** | 低值/历史 | 默认不查；仅追溯历史决策时回看 |
| **弃用** | 不取材 | 已被替换、属遗留体系或含密钥配置，不进入新项目 |
| **SCOPE** | 范围待定 | 涉及新 APC 未明确纳入的功能，取材前需人类范围决策（见 §6） |

> 注意：P1/P2/P3 是"挖掘优先级"，不是把旧文档升级为权威。任何旧文档都不是本项目规则源。
