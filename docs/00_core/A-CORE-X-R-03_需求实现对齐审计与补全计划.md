# Binder 需求实现对齐审计与补全计划（程序级报告 · 2026-07-02 盘点）

## §1 审计范围与方法

回应人类提问：「需求是否实现完整？是否有遗漏规则链？是否有因颗粒度不够导致的实现缺口？」

对照四源交叉验证（非单看审计脚本——脚本仅捕获"已注册规则无 @GOV"这一浅层信号）：

1. **设计层**：各模块 M-D 的 `REQ-*` 定义、M-T 的 `REQ_MAP`（REQ→RULE/CHAIN 映射）。
2. **索引层**：A-CORE-C-R-01_ADUS 的链路视图 / 规则视图（RULE/CHAIN → @GOV 代码块）。
3. **代码层**：src / src-tauri 真实实现扫描（占位/桩/样例标记、命令注册、模块实体）。
4. **债务层**：A-CORE-X-R-01 债务台账（A/B/C）、A-CORE-X-R-02 占位 triage、`npm run governance:audit`。

## §2 项目阶段基准（判"完整"的前提）

项目处于 **G3 实现期**：2026-06-12 人类宣布全部客户端模块 **G2 设计闭合**（A-CORE-X-R-01 §7）。
故"完整性"须分层判：

- **设计完整性**（REQ_MAP / 链路 / 规则）：应已闭合。
- **实现完整性**（规则→真实代码）：在建，允许显式延期（APC §5「闭合标准不是零未决，而是无未经显式处理的未决」）。

本审计的价值在于区分：**（i）设计内的合法延后**（非缺陷）、**（ii）真实实现缺口**、**（iii）文档滞后**。

## §5 实现颗粒度缺口（问③：颗粒度不足导致的实现缺口）★核心发现

"形式上有 @GOV" ≠ "语义真实现"。按严重度分三级：

### 5.1 🔴 A 级：AI 模型边界整体桩化（最大实现缺口，跨 AG / DE）

核心 AI 价值链的链路与规则齐备、下游设施完整，**唯上游 AI 产出桩化**：

| 缺口 | 证据 | 现状 |
|---|---|---|
| **AG-TURN 模型调用桩化** | `src-tauri/src/lib.rs:935`「回桩化助手回复，模型实际调用与流式分片落实现期（云网关接通）；本桩保留门禁先于模型不变量」 | 门禁 / 信封 / 回合状态机真实；**模型产出为桩** |
| **DE 真实产出未接线** | `src/services/deService.ts:39` `generateSampleDiff`「确定性变换绕过桩模型」；`Composer.tsx:278` / `DiffCard.tsx:66` 仍挂"生成示例/重新生成" | diff **生命周期**（`de.generate_diff` 持久化 / accept·reject·expire / locate / WS apply）**真实且可测**；**内容源为样例**，真实"模型→ChangeProposal"未接 |
| **AG-TOOL 工具回合最薄** | `ToolCallCard.tsx`「占位演示态，真实工具回合由 SM-AG-01 tool 段驱动（后续 PI）」；AG-TOOL 链仅 2 代码块 | 工具调用回合实质未落地 |

**根因判定**：AI 产出依赖云 AI 网关（`CLOUD-INVOKE`/`CLOUD-GATE`），而 ACCT/ENT/CLOUD 属 **C 类待云端独立 APC**（台账 §5）。客户端无网关可调，故 AI 产出桩化属 **设计内延后（合法）**，非疏漏；但**当前"AI 原生"核心价值链尚不可端到端跑通**——这是从"可演示"推进到"可用"的关键路径。

## §8 结论

1. **设计完整性（链路/规则/REQ_MAP）：无遗漏。** 22 链路、65/66 规则、73 REQ 两级追溯均闭合。
