# Binder 云端服务 APC（项目级 AI 开发宪章 · 独立）

> 立项依据：2026-06-12 人类确认四项决策——落点本仓库 docs/02_cloud/、模块化单体、
> Node/TypeScript、复用同款治理且 audit 阻断；草案内容与路径经人类确认后落地（CLAUDE.md §10
> bootstrap 豁免）。

## §1 项目身份

**是什么**：Binder 商业化云端服务——**Node/TypeScript 模块化单体**（单服务进程，内部按模块
边界隔离，与客户端 MODULE 治理同构），承载四个模块：

| module_code | 职责 |
|---|---|
| AUTH | 认证、用户身份库（PII 最小化：邮箱级身份）、设备/会话管理（含强制下线） |
| GW | AI 网关：服务端持 provider 密钥、统一代理模型调用、流式转发、用量计量上报、BYOK 密钥加密保管（与身份数据分离） |
| LIC | 订阅、计费、用量额度；以 user_id 关联 AUTH 身份（不复制身份数据） |
| PORTAL | 个人账户门户（Web 前端，消费三模块 API）：订阅管理与购买、账单/发票、用量明细、设备与会话管理、BYOK 密钥管理、资料与安全、账号注销（承路线图 §8.5 能力清单） |

**为谁而建**：Binder 桌面客户端（唯一程序化消费方，经 A-SYS-I-P-03 契约）与门户用户。

**当前阶段**：greenfield 设计期（无旧文档原料，台账 §4.15）；驻留客户端仓库 `docs/02_cloud/`，
代码开发启动时迁出至独立仓库。

**明确不做**：
- 不存储用户创作内容（客户端本地优先，REQ-CORE-001 的服务端对偶）
- **不留存模型调用正文**——调用内容在 GW 仅瞬时过境，只留脱敏计量元数据（BR-SYS-DATA-004，
  本宪章的最高级产品承诺，弱化即产品边界变更）
- 不做通用 AI 平台 / 对外开放 API（v1 仅服务 Binder）
- v1 不做桌面内支付（购买一律在 PORTAL）

## §2 开发方法论

- **文档先行，契约即法**：客户端对接契约的 SSOT 是 **A-SYS-I-P-03**（CLOUD-AUTH/GATE/INVOKE
  三链、SM-SYS-01、统一错误形状）；**云端不得单方变更接口语义**——任何接口变更须与客户端侧
  双侧复核并回写 A-SYS-I-P-03，留痕于两侧变更记录。
- **完成定义**：契约测试通过（对 A-SYS-I-P-03 接口骨架的双侧契约测试）+ governance:audit 通过
  + 状态机转移测试矩阵覆盖（沿用 APC §6 同款阈值与必备字段）。
- **AI 角色**：与客户端同款——AI 在 ADP 管控下执行开发任务，门禁晋级由人类宣布；技术债务
  显式记债不隐藏。

## §3 文档体系声明

- 三层体系同客户端：L1 功能需求（D，载 REQ）→ L2 技术设计（T/S/I-P，规则 SSOT）→ L3 计划（L）；
  编号格式 `{状态}-{模块}-{范畴}-{类型}-{NN}`，模块编码 AUTH/GW/LIC/PORTAL（CLOUD 为域级前缀，
  仅用于域级文档如本宪章）。
- **驻留本仓库期间的硬约定**：`docs/02_cloud/` 下文档**只载 REQ 块与叙述性设计，不得放置任何
  注册类治理块**（MODULE / RULE / CHAIN / CONSTRAINT / TERM）——本仓库 governance:generate
  递归扫描 docs/ 全树，放置即污染客户端 ADUS。注册类治理（含云端 ADUS 生成）随独立仓库迁移启用。
- 独立仓库建立时：本宪章及 02_cloud 全部文档迁出 → 新仓库 governance.config.json 指向本宪章 →
  运行 generate 建云端 ADUS → 客户端仓库中以 X 状态保留迁移指针。

## §4 ADU/ADP 启用声明

- **复用同款治理工具链**：ADU.md / ADP.md / CLAUDE.md 体系与 governance 脚本在独立仓库原样启用。
- **audit 策略：阻断**——audit failed 阻断 READY/合入/发布（与客户端一致）；密钥保管、门禁
  裁决、计费计量三块代码为强制 @GOV 标注域。
- 状态机强制阈值同 APC §6；服务端裁决链（门禁裁决、计量、BYOK 保管）进入实现前须建机登记。

## §5 AI 执行边界（客户端 APC §13 同款 + 云端特有禁区）

AI 不得自主决定（须人类批准或由人类执行）：

```
不得弱化 BR-SYS-DATA-004：不得持久化模型调用正文；日志、监控、错误上报、
  调试输出中均不得留存调用正文（含截断片段）
不得自行变更计费逻辑、额度规则、订阅档位语义
不得变更密钥保管方案（加密方式、存储分离边界）
不得弱化门禁裁决语义（X-FORBID-002 服务端对偶：裁决唯一在服务端）
生产数据库的任何操作（迁移、修数、删除）由人类执行，AI 仅产出脚本与方案
不得引入对外开放 API 或第三方数据共享（产品边界变更须 APC 授权）
```

生成内容真值等级、暂停触发条件沿用客户端 APC §13 同款条款。

## §6 版本与变更管理

- **接口契约联动**：A-SYS-I-P-03 是双边契约——云端接口变更须双侧复核、双侧变更记录留痕；
  破坏性变更须客户端版本协同（最低客户端版本声明机制，G2 设计）。
- **本宪章变更门槛**：draft 期变更须人类确认；升 baseline（核心链路定义齐备 + 规则注册实质化）
  与 controlled（生产/对外发布）由人类宣布，APC controlled 后变更走两轮审批（提案→确认）。
- 版本策略：semver；与客户端发布通道（alpha→beta→RC→GA）联动的部署节奏在 L3 计划层定义。
