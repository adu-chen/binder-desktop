# Binder TPL 模板/工作流功能需求描述（L1）

## §1 文档定位

```
产品概述(REQ-CORE-005) → 本文(REQ-TPL-*) → REQ_MAP → TPL L2 规则(SSOT) → 代码(@GOV)
```

TPL 是**模板与工作流模块**：管理写作模板（文档结构/提示模板）与模板化工作流（多步写作流程的
可复用编排），本地存储（REQ-CORE-005）。TPL 依赖 AG/WS；其执行**不自带通道**——单文档回合经
AG、多文件构建经 CBT。取材台账 §4.13（原料不为权威）。

## §2 模块定位与职责

| # | 职责 | 锚定 |
|---|---|---|
| T-J1 | 模板本地存储与管理：文档模板/提示模板的增删改与组织 | REQ-CORE-005 |
| T-J2 | 模板应用：以模板创建文档 / 以模板发起 AI 回合输入 | REQ-CORE-005 |
| T-J3 | 模板化工作流：多步写作流程的定义与可复用执行（执行经 AG/CBT） | APC §4.1 |
| T-J4 | 离线与不上云：模板与工作流数据本地存储、离线可管理 | REQ-CORE-005/001 |

> 边界澄清：TPL 是**编排定义层**——工作流每一步的实际执行经 AG 回合基建（门禁前置）或 CBT 构建
> 编排；产物落盘同样走 diff 路径（X-FORBID-006）。TPL 不持模型调用通道、不持写盘通道。

## §3 能力范围（TPL v1）

**IN**：模板（文档结构/提示）的本地存储、组织与管理；模板创建文档与模板化回合输入；工作流
定义（步骤序列 + 每步模板/指令）与执行编排（委托 AG/CBT）；重启可恢复。

**OUT**：模型调用与门禁（AG）；多文件构建执行（CBT）；diff 裁决与落盘（DE/WS）；模板市场/云
分发（v1 OUT，APC §1 插件市场 OUT 同域）；工作流表达模型细节（TPL L2）。

### §3.1 Agent 1.0 Profile 边界

模板与工作流是保留的产品路线能力，但不进入 `agent-edit-1.0` 默认 Runtime Profile。1.0 不提供模板
自动注入、模板化工作流执行或以模板绕开当前回合的最小工具授权；用户在后续阶段明确发起模板/工作流时，
其新建与编辑产物仍须服从 REQ-CORE-010 的受控预览和显式保存链路。

## §4 代表性流程（契约级，APC §7）

**T1 · 模板应用与工作流执行**

| step | actor | input | action | output | next | exception |
|---|---|---|---|---|---|---|
| 1 | 用户 | 选定模板/工作流 | TPL 实例化（文档骨架/回合输入/步骤计划） | 实例化产物 | 2 | 模板缺失/损坏→明确错误，不产生半成品 |
| 2 | AG/CBT | 步骤计划 | 逐步执行（AG 回合或 CBT 构建，均过门禁） | 步骤产物（经 diff 路径） | 3 | 步骤失败→工作流暂停可恢复，不静默跳步 |
| 3 | 用户 | 步骤产物 | 裁决落盘（DE/WS），继续/中止工作流 | 工作流完成/中止 | 终态 | 中止不残留半成品落盘 |

## §6 模块边界与约束（边界闭合）

- **执行委托**：TPL 定义编排，执行经 AG/CBT（门禁前置、diff 路径），TPL 无独立模型/写盘通道。
- **本地优先**：模板/工作流数据本地；模板市场/云分发 v1 OUT。
- **状态机阈值**：工作流执行编排（多步、可暂停恢复）疑似状态化链路——**G2 必须评估建机**
  （不预判豁免，与 REF/KB 的请求-响应式不同，多步编排更接近 CBT 构建语义）（§7 TPL-02）。
- **L4 原料边界**：取材台账 §4.13，原料不为权威。
