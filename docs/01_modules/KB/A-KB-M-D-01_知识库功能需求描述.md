# Binder KB 知识库功能需求描述（L1）

## §1 文档定位

```
产品概述(REQ-CORE-005) → 本文(REQ-KB-*) → REQ_MAP → KB L2 规则(SSOT) → 代码(@GOV)
```

KB 是**本地知识库模块**：用户主动组织的参考资料库（资料、设定、素材），本地存储、可检索召回、
向 AI 回合供给（REQ-CORE-005）。KB 依赖 WS 与 AG（消费方）。与 AST 的分界：知识库是**用户主动
组织的参考资料**，记忆是**协同沉淀的跨回合事实**（A-AST-M-D-01 §2）。取材台账 §4.12。

## §2 模块定位与职责

| # | 职责 | 锚定 |
|---|---|---|
| K-J1 | 条目本地存储与组织：知识条目的增删改、分类/标签组织，用户可见可管理 | REQ-CORE-005 |
| K-J2 | 内容入库：自 workspace 文档/外部文本导入建库，入库经用户主动操作 | REQ-CORE-005 |
| K-J3 | 检索召回供给：按查询/相关性召回条目，供给 AG 回合上下文 | A-AG-M-T-01（BR-AG-DATA-001） |
| K-J4 | 离线与不上云：知识库数据本地存储、离线可用，不上行云端 | REQ-CORE-005/001 |

## §3 能力范围（KB v1）

**IN**：知识条目本地存储/组织/管理；从 workspace 文档与外部文本入库；检索召回与 AG 供给；
重启可恢复。

**OUT**：上下文组装裁剪（AG）；记忆（AST）；@mention 直接引用 workspace 文档（REF，KB 条目是否
纳入 @mention 待 REF-01 联动）；知识库云同步（v1 OUT）；检索技术选型与索引实现（KB L2/实现期）。

## §4 代表性流程（契约级，APC §7）

**K1 · 入库与检索供给**

| step | actor | input | action | output | next | exception |
|---|---|---|---|---|---|---|
| 1 | 用户 | workspace 文档/外部文本 | 主动入库（可编辑分类/标签） | 知识条目 | 2 | 入库失败→统一错误形状，库保持一致 |
| 2 | AG 回合 | 查询意图 | KB 检索召回相关条目 | 召回集（含来源） | 3 | 无相关→空集（非错误） |
| 3 | AG | 召回集 | 组装进回合上下文（AG 裁剪） | 注入完成 | 终态 | 条目已删除→不召回，无悬空 |

## §6 模块边界与约束（边界闭合）

- **本地优先硬边界**：库数据本地、离线可用；检索选型不得引入内容上行（REQ-KB-004 为 G2 选型
  硬边界）。
- **入库主动性**：AI 不静默建库（与 AST 写入可控同构的可控语义）。
- **供给边界**：KB 召回、AG 组装；跨模块结构经 SYS（X-SHARED-001）。
- **状态机阈值预判**：入库与检索为请求-响应式，预判豁免建机；若 G2 引入异步索引构建编排则建机
  （同 REF §6 复核模式），G2 复核。
- **L4 原料边界**：取材台账 §4.12，原料不为权威。
