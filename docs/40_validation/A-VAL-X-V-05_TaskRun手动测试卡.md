# A-VAL-X-V-05 · V-S7 手动测试卡（修订版）：受限 TaskRun 编排（SM-AG-04 三层分离）

文档职责：受限 TaskRun（TERM-AG-015/016/017/018 · BR-SYS-STATE-008）**真实环境手动测试执行材料**——
逐用例给出前置条件、操作步骤与**明确预期效果**（可观察、可判定通过/失败）。
对应 A-VAL-X-V-04 §4.11 V-S7 的人类观察项执行面。

测试对象：R5-B 冻结基线 + AG-1.0-TASKRUN-REWORK（阶段 0-4）重构后代码（三层分离 / DecisionRequest /
TaskPlan / 确认 gate / 实时状态 / 片段内多卡）。

## 0. 测试环境准备

- 启动应用（`npm run tauri dev`），确认 agent-edit-1.0 模式可用；打开 workspace 与文档（如 `notes/a.md`）。
- 确认 Provider/模型可用；网关连通。
- **验证位置**：
  - 信息流**底部**（Composer 上方）：回合进行中显示实时"当前动作"状态条（如"正在读取 a.md"）；
  - 任务级确认：**DecisionRequest 卡**（权限/方案/范围/人工确认，带"确认/取消"按钮）出现在信息流内；
  - DiffCard：只确认**内容**（接受→应用预览；保存→落盘）；
  - 回合终态（等待确认/等待补充/完成/失败/中断）由运行事件驱动呈现。
- 状态判定标准：每条「预期效果」逐项核对；**全部符合 = 通过**。

## T1 · 回合创建并完成（只读分析）

| 项 | 内容 |
|---|---|
| 前置 | 新会话；当前打开 `notes/a.md` |
| 步骤 | ① 输入"总结当前文档内容，不要修改"并发送；② 等待回合完成 |
| 预期效果 | 1. 回合中信息流底部出现状态条（"正在读取 a.md" → "正在生成回复…"），随事件变化。<br>2. 回合结束状态条消失，回复完成（阶段结果）。<br>3. **无** DecisionRequest 卡、**无** DiffCard（只读无提案）。 |
| 通过标准 | 状态条实时出现并消失；无确认点 |

## T2 · 编辑回合：DiffCard 只确认内容（三层分离）

| 项 | 内容 |
|---|---|
| 前置 | 新会话；`notes/a.md` |
| 步骤 | ① 输入"把第一段加粗"并发送；② 等待 DiffCard 出现；③ 接受 DiffCard |
| 预期效果 | 1. DiffCard 出现（内容修改建议），可预览/接受/拒绝。<br>2. 状态条随步骤变化（读取→生成修改建议）。<br>3. **关键（三层分离）**：接受 DiffCard 只应用内容预览（ED 草稿），**不改变任务状态**——没有"任务级确认"卡出现；<br>4. 回合结束后 DiffCard 保持"已接受 · 待保存"；**任务无"等待确认"态**（Diff 裁决不驱动 TaskRun）。 |
| 通过标准 | 内容确认不产生任务级确认点 |

## T3 · 同片段连续多 Proposal（片段内多卡 + 前卡失效）

| 项 | 内容 |
|---|---|
| 前置 | 新会话；`notes/a.md` 较长（可分多批） |
| 步骤 | ① 输入"把整篇文档改成正式风格，分多批生成修改建议"并发送；② 观察本回合内是否出现多张 DiffCard |
| 预期效果 | 1. 同一执行片段内模型**无需等待接受**即可连续提出多张 Proposal（多 DiffCard）。<br>2. 后一张卡基于前一张成功预览后的**最新 LogicalState**；前卡因基准推进**失效**（不可再接受/拒绝），不形成补丁栈。<br>3. 若模型本轮只出一张卡并停住：属行为层（可结合 Prompt 修正后复测），记录现象。 |
| 通过标准 | 片段内多卡连续提出；前卡失效规则生效 |

## T4 · 任务级确认（DecisionRequest）后自动下一片段

| 项 | 内容 |
|---|---|
| 前置 | 存在触发任务级裁决的场景（权限/方案/范围/人工确认，如需要额外权限的工具或模型主动请求方案确认） |
| 步骤 | ① 发起会触发 DecisionRequest 的任务；② 等待 DecisionRequest 卡出现；③ 点"确认" |
| 预期效果 | 1. DecisionRequest 卡出现（按 kind 显示"需要权限/方案确认/范围确认/人工确认"）。<br>2. **关键**：确认后**自动开始下一执行片段**（模型继续推进，无需再输入聊天消息）；绝不后台续跑（无确认不推进）。<br>3. 点"取消"→ 任务 Cancelled（停止未开始步骤，保留已预览内容）。 |
| 通过标准 | 任务级确认驱动片段推进；取消正确终止 |

## T5 · 新消息不绕过待确认（gate）

| 项 | 内容 |
|---|---|
| 前置 | 完成 T4 的 DecisionRequest 卡出现（尚未裁决） |
| 步骤 | ① 在 DecisionRequest 未裁决时，直接在输入框发送任意新消息 |
| 预期效果 | 1. 新回合**被拒绝**：提示 `AG_DECISION_PENDING`（存在待确认的任务级裁决项）。<br>2. 待确认状态不被绕过（任务状态不被任意新消息改回执行中）。<br>3. 完成裁决后才可继续。 |
| 通过标准 | 未决确认时新消息被 gate 拦截 |

## T6 · 实时状态流（底部当前动作）

| 项 | 内容 |
|---|---|
| 前置 | 新会话 |
| 步骤 | ① 发送"先读取整个文档，再修改第二段"；② 回合进行中观察信息流底部 |
| 预期效果 | 1. 底部状态条**实时**反映当前动作（"正在读取 a.md" → "正在执行工具 read_doc" → "正在生成修改建议"），由事件驱动、非事后查询。<br>2. 回合结束状态条收敛（消失或显示终态结论）。 |
| 通过标准 | 状态条随回合事件实时变化、回合结束收敛 |

## T7 · 失败终态

| 项 | 内容 |
|---|---|
| 前置 | 可断网 |
| 步骤 | ① 发送回合；② 进行中断网/触发网关拒绝 |
| 预期效果 | 1. 回合失败：状态条显示失败结论；任务终态 Failed（不自动重试）。 |
| 通过标准 | 失败终态如实呈现、无自动重试 |

## T8 · 取消终态

| 项 | 内容 |
|---|---|
| 前置 | 新会话 |
| 步骤 | ① 发送回合；② 进行中点击"停止" |
| 预期效果 | 1. 任务 Cancelled（停止未开始步骤）；已成功预览内容保留不回滚。 |
| 通过标准 | 取消正确、预览保留 |

## T9 · 历史恢复

| 项 | 内容 |
|---|---|
| 前置 | 已有 TaskRun 历史（完成/失败/中断等） |
| 步骤 | ① 重启应用；② 打开同一会话 |
| 预期效果 | 1. 历史回合/TaskRun 数据正确恢复（DB task_runs/decision_requests）；状态与退出前一致。<br>2. 顶部无重复卡；底部/信息流呈现正确。 |
| 通过标准 | 恢复状态一致、无重复呈现 |

## T10 · 中断恢复（不跨重启续跑）

| 项 | 内容 |
|---|---|
| 前置 | 新会话 |
| 步骤 | ① 发送回合；② 执行中直接退出应用；③ 重启打开同一会话；④ 再发送新回合 |
| 预期效果 | 1. 重启后旧活动 TaskRun 显示 Interrupted（可重试，不自动续跑）。<br>2. 新回合新建（retry 语义），不沿用旧执行上下文。<br>3. 无自动续跑旧任务。 |
| 通过标准 | 中断可重试、不自动续跑 |

## T11 · 跨会话隔离

| 项 | 内容 |
|---|---|
| 前置 | 两个会话标签 |
| 步骤 | ① 会话 A 有任务/确认点；② 切到会话 B 发送回合 |
| 预期效果 | 1. 各会话的状态条/确认卡/消息互不串线。<br>2. 会话 A 的待确认不被会话 B 的新回合绕过。 |
| 通过标准 | 会话隔离 |

## T12 · 澄清等待（WaitingClarification）

| 项 | 内容 |
|---|---|
| 前置 | 新会话 |
| 步骤 | ① 输入歧义请求触发澄清；② 澄清等待中取消 |
| 预期效果 | 1. 澄清等待为**非终态**（不伪装工作中）；补充输入使原 AgentTurn 从 AwaitingClarification 回到 Assembling，不创建新 AgentTurn。<br>2. 澄清中取消 → 任务 Cancelled。<br>3. 澄清路径**不受**确认 gate 影响（不误拦）。 |
| 通过标准 | 澄清非终态、gate 不误伤澄清 |
